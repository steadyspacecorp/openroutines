# Open Routines

The framework for running simple, secure, and durable autonomus AI agents.

## Background

An autonomous AI agent is software that leverages AI models to fulfill a job description. It pursues objectives by working with context and running routines on it's own. Furthermore, it gets better at it's job by continously improving the context it uses based on the "memory" of what it did successfully.

For example, a Product Management agent that gathers user research into themes, updates specifications from technical constraints, and checks that documentation hasn't drifted away from what's shipped. Or an IT Ops agent that triages tickets, monitors licenses, and surfaces compliance issues.

Given that definition, Open Routines is an opinionated way to generate and maintain a single autonomous agent in it's own runtime, and to treat it like any other deployed software, with established lifecycle, security, and durability patterns.

## What it does

Use Open Routines to generate a runnable agent in the form of a git repository with a deployable Docker container. The repository contains agent configuration details, skills, structured memory, encrypted credentials, and a set of routines in the form of markdown files. Under the hood, Opencode handles the back and forth the AI models you choose.

You work on an Open Routines -generated agent (ORA) the same way you would with any software project: configure and test locally, and then deploy the project via git and Docker. If your git origin is GitHub, Gitlab, or the like, you can also hook up standard CI/CD hooks.

The heart of the agent are the markdown files that describe each routine. Using frontmatter, you explicitily scope the schedule, skills, credentials, and the model. The body of the file is the prompt.

```markdown
---
schedule: "0 9 * * *"
timeout: 5m
active: true
skills: []
credentials: []
model: []
---
Share one interesting, true fact about this day in history that's related to the company mission, vision, and strategy. Just print it as your output -- it goes to the container logs.
```

Git is also the mechanism for backing up the memory generated by the agent as it does it's job. So switching deployment platforms is a cinch.

### What it doesn't do

This is not a platform for maintaining a fleet of agents. You can run as many routines as you want, but the idea is that each ORA is performing a job.

An ORA doesn't have a "gateway" for chatting with it as way to develop it. You can use a coding agent _locally_ to work on it, and there is an AGENTS.md file to make that easy.

## Getting started

Clone or fork this repo.

Run bin/setup to install dependencies
Run bin/scaffold agent-name. This will create another repo at ../agent-name, using the template

Or, if you are adventurous.

curl open-routines | install.sh
openroutines scaffold

cd ../agent-name


bin/configure (idempotent)
  job description
  creates master key
  creates default model
  sets upstream fork

bin/status
  master key
  default model
  active routines
  inactive routines
  skills

bin/ci

~~bin/update pull from upstream fork~~

bin/routines list
bin/routines new
bin/routines edit
bin/routines activate
bin/routines deactivate
bin/routines remove
bin/routines run <name>
bin/routines test <name>

bin/skills new
bin/skills list
bin/skills remove
